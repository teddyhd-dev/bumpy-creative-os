# Bumpy ads intelligence: agent instructions

Bumpy is an international dating app. This folder turns weekly Meta and TikTok exports and App
Store proceeds into a dashboard and a ranked action list, so the team can **scale paid spend week
after week without losing real return**. Read `docs/bumpy-ads-intelligence-spec.md` §0 (the
model) and §19 (open decisions) before changing anything.

## The model in one line
creative → adset / ad group → country → App Store / Play money, with each channel's own reporting
beside the chain. Creative decides how much an adset can spend and for how long. Structure decides
which countries the money goes to. Each country returns its own amount of store money. Meta and
TikTok each credit themselves part of it, on their own rulers. Since Singular (our MMP) started
feeding Meta (iOS 23 Feb, Android 9 Mar 2026), Meta's share is about 0.7× what it was: a different
ruler, not a weaker business (spec §3.3). Store money is the one currency for both channels (§3.4).

## Folder map
- `data/raw/<source>/`: every export, **never edited or deleted**. Sources: `adset/`, `ad/`, `country/` (Meta), `tiktok/`, `apple/`, `play/` and `singular/` (not used yet).
- `data/model/`: joined model (generated by `engine/model.py`).
- `data/log/`: `at_bats.csv` (refreshes and verdicts), `decisions.md` (bar, retirements, tests).
- `engine/`: pipeline. `run_all.sh` runs it in order: `build.py` → `rootcause.py` → `creative_relay.py` → `model.py` → `eras.py` → `channels.py` → `holistic.py` → `tickets.py` → `board_export.py` → `report.py` → `make_dashboard.py`. `report.py` builds the Tuesday report (`output/board/report_<week>.json`, spec §20.7). `tickets.py` builds the ticket queue and at-bat verdicts (spec §6, §20). `tiktok.py` loads the TikTok exports. `settings.py` holds the measurement eras (switch dates), the ROAS bar per ruler, and the at-bat and ticket settings (`ATBAT`, `TICKET_WEIGHTS`).
- `output/data/`: datasets the dashboard reads (generated).
- `output/dashboard/page.html`: the dashboard page (source of truth). `index.html` is generated from it.
- `output/updates/`: one weekly note per run, `YYYY-MM-DD.md`.
- `personas/<Persona>/`: persona library (`bible.md`, `winners/`, `voice/`, `signals/`).
- `docs/`: spec, `naming-adset-v8.md`, `naming-ad-v5.md`, `board-guide.md`.
- `output/board/`: the board's engine documents (`*.json`) and the board page source (`board.html`). `engine/board_export.py` writes them; `engine/personas.py` reads the Notion persona cards from `data/raw/notion/`.

## Commands (run from this folder)
- Install once: `python3 -m pip install -r requirements.txt`
- Rebuild everything: `bash engine/run_all.sh` (takes about 30 seconds)
- See the dashboard: `python3 -m http.server 8000 -d output`, then open http://localhost:8000/dashboard/

## Export file names
`<prefix>_<YYYY-MM-DD>_<YYYY-MM-DD>.csv` (start and end dates). Prefixes: `adset_`, `ad_`, `country_`, `tiktok_`, `apple_proceeds_`, `play_`, `singular_`.
Exports must **start on a Monday** (Meta's "Week" breakdown counts 7-day blocks from the start date).
Overlapping files are fine: the newest file wins for overlapping days (`engine/files.py`).
If a file arrives with another name, rename it to this pattern from its `Reporting starts`/`Reporting ends` columns.

## Weekly routine ("run the weekly update")
1. Check the new files in `data/raw/*/`, rename if needed, and confirm each starts on a Monday.
2. Run `bash engine/run_all.sh`. If a step fails, fix the code, not the data.
3. Read `output/data/checks.csv` and list anything new: naming errors, code collisions, unmapped countries, missing columns.
4. Write `output/updates/<today>.md` with these sections, in this order, using only numbers from `output/data/`:
   1. **Money:** spend by channel vs App Store proceeds per week, and the proceeds per iOS dollar by channel (`ov_facts.csv`, `ov_weekly.csv`, `ch_facts.csv`, `ch_store.csv`).
   2. **Actions:** the rows of `ov_actions.csv`, each with owner and evidence.
   3. **Adsets:** alerts and `decay_due` rows from `grid.csv`, biggest leak first. Say which bar they were judged on.
   4. **Markets:** biggest country moves (`mk_country.csv`), US share.
   5. **Creatives and tickets:** the top tickets above the capacity line (`tk_queue.csv`, `tk_facts.csv`), with type, current #1 and reign, strikes and the first J1 candidate; at-bats with a new week-1 read or week-4 verdict (`tk_atbats.csv`); any Review ticket first; resurrection candidates (`tk_resurrect.csv`).
   6. **New batches:** batches seen for the first time in `data/raw/ad/`. Draft a one-line hypothesis for each, marked *draft*, for the strategist to confirm.
   7. **Data checks.** Include any finding in `era_compare.csv` whose verdict is not "Holds".
   If nothing needs action, say so in one line.
5. Append confirmed refreshes and their verdicts to `data/log/at_bats.csv` only after a human confirms them (in the retrospective, spec §20.4).
6. **Sync the Creative Board** (https://claude.ai/artifact/MFtoxXwScrbATaY5jNhv2U). Read the `engine` collection with ArtifactData to get versions, then write `output/board/queue.json`, `people.json`, `codes.json`, `log.json`, `archive.json`, `personas.json` to `engine/<name>` in one batch with `if_version`, and create `history/<adset week>` from `output/board/history_<week>.json` (never overwrite an older week). Write `output/board/report_<week>.json` to `reports/<adset week>` (create; if this week's exists, replace it with `if_version`). Never write to `report_notes`: those are the presenter's edits. Then refresh the analysis dashboard (https://claude.ai/artifact/QJnA8xeAWjv2D8NVozMp8X): upload each changed CSV from `output/data/` as an asset (one call per CSV) and point its `datasets/<name>` document at the new `/_blob/` url; if `output/dashboard/page.html` changed, write it to `files/index.html` as `{text}`. Never write to `work`, `signals`, `manual` or `team` except: in `work`, `results.<ticket id>` (week-1 share, verdict per covered adset), `result` (the brief's summary: won N of M) and its status when the export shows the ads live (TESTING) or the week-1 read is in (RESULT READY); in `signals`, `metrics` (views, likes, comments, shares, saves, running_since) read from the link with the built-in browser, only where the page shows them. Match work documents to ads by their `ad_names`, or by concept code + batch + the covered adsets.
7. The **Tuesday report** is the board's Report tab (step 6). If asked for it in another form, follow spec §20.7 in that order, using only numbers from `output/data/`, and mark every insight and action item *draft* for the presenter.
8. Change the spec only when a rule changes, and add a changelog entry when you do.

## Data rules
- **Measurement eras (spec §3.3).** Never compare absolute Meta ROAS, purchases, installs, IPM or click → install across a measurement switch, in numbers, notes or charts. Judge each week on the bar of its own ruler (`engine/settings.py`). Relative numbers compare an adset with its own OS in the same week. Store money is the check on every era.
- If the user reports a new measurement change (MMP, SDK, attribution setting, tracking link), add its dates to `engine/settings.py`, propose a restated bar from Meta ROAS for the same store money before and after, and log both in `data/log/decisions.md`. Don't apply a new bar until the creative lead confirms.
- **Channels (spec §3.4).** Never compare Meta's ROAS level with TikTok's: each credits itself. Compare channels only through App Store money (`ch_store.csv`) and geo tests. TikTok value counts only on ad-group weeks with $20+ spend; value on idle ad groups is reported as "value without spend".
- **Judging creatives (spec §6.2).** Never judge a creative by its own ROAS row: within a week an ad's ROAS sits near its adset's. Judge it by delivery (week-1 share, became #1 within 4 weeks) and by the adset's relative ROAS after it took over. Verdicts are provisional at week 1 and final at week 4; a #1 in weeks 5–12 is a late hit. Strikes count only in a turnaround (adset under green the week before); misses into a healthy adset are fouls.
- Watch time comes from counts (3-second plays, ThruPlays, plays at 25–100%), never from `Video average play time` (whole seconds).
- Revenue = Purchase ROAS (7-day click) × spend. Don't use the in-app conversion value column; it misses web purchases.
- Weeks run Monday to Sunday. Ad and country exports are spread evenly over their days.
- Only Purchase and Sales objectives are judged on ROAS.
- Meta country codes map to App Store storefronts in `engine/model.py` (`OVERRIDE`). Add new territories there.
- Persona and language values come from `docs/naming-adset-v8.md`. Legacy names are mapped in `engine/build.py` and `engine/adparse.py`.
- Concept codes must be unique ignoring case. Flag collisions; never merge them silently.

## Boundaries
- Never edit, move or delete anything in `data/raw/`.
- Don't change thresholds, the profit bar or ROAS zones without a decision from the creative lead. Record each decision in `data/log/decisions.md` and the spec changelog.
- Don't upload data anywhere, and don't put credentials in this folder.
- After editing `output/dashboard/page.html`, run `python3 engine/make_dashboard.py`, then open the page and check that every tab draws without console errors.
- Keep claims honest. App Store proceeds include renewals and organic users. The per-dollar figures are correlations unless a test says otherwise. Android can't be judged until Google Play data is in `data/raw/play/`.

## Current state (27 Oct 2026)
